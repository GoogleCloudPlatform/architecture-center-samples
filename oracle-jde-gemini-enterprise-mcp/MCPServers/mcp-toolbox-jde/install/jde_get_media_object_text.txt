Returns the plain text of a JD Edwards media object attachment, 1,000 characters per call. JDE stores text media objects as UTF-16 and often as RTF; this tool decodes both, and also reads PDF or Word files when they are kept in the database. Give the object name and text key exactly as jde_get_media_object_attachment returns them, plus the sequence number. The response says whether the object has content (media_object_status: OK, NOT_FOUND, TOO_LARGE over 50 MB, or NO_CONTENT), whether text could be read (text_status: OK, NO_TEXT, ERROR with the reason), how many chunks there are and whether more follow; call again with the next chunk number until has_more is N.
File, image and link media objects (types 1, 2 and 5) keep only a file name or URL in the database, and the file itself is on the JDE server, so they come back as NO_CONTENT: report the file name from jde_get_media_object_attachment instead of inventing content. Use jde_get_media_object_base64 for the stored bytes.
Attachments can hold personal data. The text is returned as stored; masking belongs to the calling skill.
Underlying Tables: F00165 (through the database package JDE_AI.XX_AI_ATTACHMENT_PKG, installed by a DBA from jde/install).
Security Context: JDE media object data; JDE does not enforce row security in the database, so use the PL/SQL wrapper and an authorised user in production.
