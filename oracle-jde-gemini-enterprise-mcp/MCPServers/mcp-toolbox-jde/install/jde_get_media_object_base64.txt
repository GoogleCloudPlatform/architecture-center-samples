Returns the bytes stored in a JD Edwards media object as Base64 text, one piece per call, so a client can rebuild a file whose text cannot be read in the database. Give the object name and text key exactly as jde_get_media_object_attachment returns them, plus the sequence number. The response gives the stored size, bytes per piece, the number of pieces and whether more follow; call again with the next chunk number, keeping chunk_bytes the same, until has_more is N, then join the base64_chunk values in order and decode them. Text media objects are stored as UTF-16 (stored_encoding UTF-16LE); decode the bytes as UTF-16 little-endian.
Only content that is stored in the database can be returned. File, image and link media objects (types 1, 2 and 5) keep a file name or URL in F00165 and the file on the JDE server, so they return NO_CONTENT. For readable text use jde_get_media_object_text instead, which is much smaller. Objects over 50 MB are refused.
Attachments can hold personal data; the content is returned as stored.
Underlying Tables: F00165 (through the database package JDE_AI.XX_AI_ATTACHMENT_PKG, installed by a DBA from jde/install).
Security Context: JDE media object data; JDE does not enforce row security in the database, so use the PL/SQL wrapper and an authorised user in production.
