# jde/tools_sec/

Generated by `scripts/build_and_validate.py` from `tools_agent/`. Do not edit; it is git-ignored and rewritten
on every build.

**Who is the user?** The Toolbox decides. `user_id` is filled from the caller's verified Google token
(`google-auth`, `clientId: ${GOOGLE_CLIENT_ID}`); a value sent in the request body is ignored.

- Every tool is wrapped in the PL/SQL security block, so the database applies that user's access rules.
- Every tool needs a valid token (`authRequired`), so calls without one are refused with 401.
- Safe to expose to callers that send their own Google token.
- Deploy: `scripts/deploy_mcp_server.sh --system jde --variant sec`

## Difference from `tools_agent/`

| | `tools_agent/` | `tools_sec/` |
|---|---|---|
| `user_id` comes from | the agent (plain parameter) | the verified Google token |
| Toolbox checks the caller | no | yes |
| Where it may run | private, agent-only service | any service callers can reach |
